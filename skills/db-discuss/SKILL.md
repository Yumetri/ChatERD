# DB 설계 토론

사용자가 지정한 기존 UTF-8 `.mmd` 경로와 질문·필요한 문맥을 입력으로 받는다. 파일이 불명확하면 질문한다. 특정 파일명·경로·테이블을 가정하지 않는다.

이 스킬의 실제 위치에서 `../../runtime/cli.mjs`를 찾는다. `.agents/skills` 연결이면 실제 위치를 확인한다. 빌드되지 않았으면 호스트에서 `node <런타임> setup`을 실행한다.

1. `node <런타임> preview <사용자가 지정한 경로>`로 뷰어를 연다. 이미 열려 있으면 중복으로 열지 않는다.
2. `node <런타임> discuss <동일한 경로>`를 실행하고 질문과 문맥을 stdin으로 전달한다. 요청을 셸 문자열에 보간하지 않는다.
3. 읽기 전용 격리 실행의 답변을 전달한다. 토론 중 호스트도 스키마를 수정하지 않는다. 실제 수정은 사용자의 명시적인 db-draw 호출로 전환한다.

격리 실행은 읽기 전용 파일 샌드박스와 조회 전용 MCP 연결을 사용한다. 외부 앱·플러그인·셸 도구를 제공하지 않으며 서버도 쓰기 API를 거부한다. 사용자 UI 편집은 별개로 허용한다.

[배치 피드백](../../references/layout-feedback.md)과 [실행 규칙](../../references/isolated-workflow.md)은 자동 전달된다. 실제 소스·이미지 버전을 확인해 논의하고, 업무 위계를 이름만으로 단정하지 않는다. 관찰·이유·가능한 조치·한계를 설명한다. 이미지가 없으면 시각 검수했다고 주장하지 않는다.

Mermaid 12 파서와 독립 SVG/ELK 뷰어를 사용한다. [명시적 설계 정보](../../references/schema-metadata.md)의 NULL·복합 키·FK 컬럼 대응도 원본 설계의 일부이며 추정하거나 시각 보정으로 변경하지 않는다. 참고 문서는 격리 실행에 전달된다.
