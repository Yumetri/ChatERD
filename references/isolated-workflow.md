# 격리 실행 규칙

draw 격리 실행은 최초 검수·오류 복구·명시적 이미지 검수용이다. 한 번 통과한 파일의 정상 수정은 호스트가 직접 수정한 뒤 CLI `check`로 자동 렌더링을 확인하며 이 독립 모델 실행을 반복하지 않는다. `review_mode: strict`는 PNG 검수가 필요하고 `automatic`은 이전 검수를 통과한 상태다. 오류가 나면 strict로 복귀하며 정상 렌더만으로 해제되지 않는다. 통과 기록은 파일 경로별로 유지된다.

도구는 현재 세션의 지정된 스키마에만 연결된다. 파일명이나 테이블 이름을 가정하지 않는다. 시작할 때 get_diagram을 읽고 content(에디터 초안), saved_hash(세션이 마지막으로 저장한 원본 해시), disk_content·disk_hash(현재 디스크 원본), version(편집 버전), render_status를 구분한다. file_conflict 또는 disk_error가 있으면 원본과 에디터·그림이 다르거나 원본을 읽을 수 없는 상태다.

## discuss
get_diagram과 get_preview만 사용한다. 수정 제안은 설명으로 전달한다. 파일·초안·그림을 수정하거나 권한을 높이려 하지 않는다. 이미지와 소스 버전이 다르거나 렌더링이 실패하면 그 사실을 먼저 밝힌다. 설명하기 전 get_diagram을 다시 읽어 버전·disk_hash가 바뀌었으면 최신 내용으로 논의를 갱신한다. 외부 파일 변경 시 disk_content를 읽되 이전 해시의 그림을 최신 설계로 설명하지 않는다. 외부 파일 변경은 초안·검수 후보와 충돌하지 않으면 자동 렌더링된다. 충돌이면 현재 초안을 보존하고 명시적 재로딩을 안내한다. 테이블 이름만으로 업무 위계를 단정하지 않는다. 실제 수정 요청은 db-draw 호출로 전환하도록 안내한다.

## draw
사용자가 지시한 설계만 표현한다. 요청하지 않은 테이블·속성·PK/FK·관계·카디널리티를 추가하지 않는다. 설계 판단이 필요한 모호함은 질문하고 저장하지 않는다. 모델링 개선은 discuss에서 논의한다.

get_diagram → stage_diagram(content,version,saved_hash) → get_preview(id) 순서로 작업한다. PNG를 직접 확인하고 공통 배치 기준의 모든 항목을 검토한다. 관계선 분포는 같은 후보의 `layout_feedback`과 함께 확인하며, 수치만으로 이미지 검수를 대체하지 않는다. 이미지가 없으면 저장하지 않는다. 문법 또는 가독성을 자동 보정할 경우 repair_of와 adjustment(syntax/visual)를 반드시 명시한다. 합쳐 최대 2회다. visual은 정상 후보를 기준으로 설계 의미가 같아야 한다. 구문 수정도 의미 선택이 필요하면 질문한다.

지원되는 보정은 direction LR/RL/TB/BT, config.er.nodeSpacing/rankSpacing, 엔티티 style/classDef의 글자 크기·색·테두리다. 사용자가 배치 조정을 요청한 경우에는 [배치 주석](schema-metadata.md)의 mode·aspect·관련 nodes·edges.via/from/to도 사용할 수 있다. 요청 범위 밖의 수동 위치는 보존한다. 지원되지 않는 좌표 형식·가짜 관계·임의 그룹·속성 숨김을 넣지 않는다. 선 분포는 [배치 피드백](layout-feedback.md)의 기본 24px 목표와 조정 순서로 검토한다. 보정한 후보의 PNG와 실제 간격을 비교하고, 수치가 없으면 측정했다고 주장하지 않는다. 남은 교차·선 간격처럼 엔진 한계인 문제는 관계를 지목해 findings에 명시한다. 글자 잘림·내용 누락·끝점을 혼동해 읽을 수 없는 그림은 통과시키지 않는다.

이미지를 받은 뒤 시각 검수에 통과한 후보만 commit_diagram(id,review:"pass",findings:[관찰 결과])로 저장한다. 도구는 이미지 조회와 렌더 성공을 검사하지만 시각적 판단 자체를 증명하지는 않는다. 충돌이나 반복 실패 시 원본을 유지하고 오류를 보고한다. 실패한 후보를 새로운 최초 후보로 위장해 보정 횟수를 우회하지 않는다.

최종 답변에는 반영한 사용자 요청, 렌더링·시각 검수 결과, 자동 보정 내용, 남은 한계만 간결하게 적는다. 이미지 파일을 생성하거나 다운로드 폴더를 탐색하지 않는다.

[명시적 설계 정보](schema-metadata.md)의 nullable·기본값·복합 제약·FK 대응은 사용자가 준 정보만 표현한다. 최신 Mermaid 12의 nullable와 subgraph를 사용하며 원본에 존재하는 제목·별칭·그룹 소속을 보정 중 보존한다. 정확한 DB 제약은 Mermaid 관계선만으로 추정하지 않는다. 상세 보기는 표시용이며 자동으로 원본을 분할하지 않는다.
